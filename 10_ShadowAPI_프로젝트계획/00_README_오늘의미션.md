## 확정 주제 (가제)

**"쿠버네티스(EKS) 환경에서 트래픽 관측 + 자산 조회 + API 명세 비교를 결합한 Shadow/Zombie API 자동 탐지 파이프라인"**

- 한 줄 요약: *문서화된 API(명세)* 와 *실제로 열려 있고 호출되는 API(관측)* 의 차이를 자동으로 찾아내고, 위험도를 매겨 리포트로 내보낸다.
- 차별점: 트래픽 미러링(수동 관측)만으로는 **조용히 열려만 있는 API**를 못 본다 → 쿠버네티스/AWS 자산 조회 + 능동 스캔을 결합해 **"트래픽은 없지만 노출된 위험 API"** 까지 잡는다.
- 신한은행 사고(07 제안서)와의 연결: 그 사고의 1차 침투 지점은 "외부에 노출됐지만 관리 사각지대에 있던 내부용 조회 API" → **API 인벤토리 관리 실패(OWASP API9)** 가 출발점이었다는 해석이 가능.

```
① 원인 분석          ② 탐지 파이프라인 구현     ③ 비교 실험              ④ 제언
왜 Shadow API가   →  명세 vs 관측 vs 자산    →  방화벽/WAF 대비      →  법규·평가 기준
생기는가(K8s,        차이 자동 탐지 +           탐지율·오탐·탐지시간     개선안 + 오픈소스
클라우드, 사람)      위험도 + AI 보조 + 리포트   측정                    공개
```
