| 스마트그리드 | 국가 기반시설 | OT 프로토콜 중심, 재현 불가 | ★☆☆☆☆ |

## 3. 통관·물류를 고른 이유

1. **구조 적합성**: 여러 회사·국가 시스템을 API로 잇는 구조 → K8s 마이크로서비스 재현에 자연스러움
2. **Shadow/Zombie 발생 요인이 풍부**: 파트너별 연동 API, 구버전 EDI 연동, 국가별 엔드포인트, 계약 종료 파트너 연동
3. **거버넌스 연결**: 관세청 전자통관시스템(UNI-PASS, 해외 수출 사례), AEO 인증의 IT 보안 항목, WCO 가이드 → "인증 기준에 API 자산 관리 항목 추가" 제언

## 4. 모의 통관·물류 플랫폼 (초안)

| 서비스 | 역할 | 심어둘 시나리오 |
|---|---|---|
| 수출입신고 서비스 | 신고서 제출·조회 | 구버전 v1 조회 API 잔존 (Zombie) |
| 화물조회 서비스 | B/L·컨테이너 추적 | 포워더 테스트용 조회 API 미등록 (Shadow) |
| 관세사·포워더 연동 게이트웨이 | 파트너 인증·연동 | 계약 종료 파트너 키·엔드포인트 잔존 (Orphan) |
| 해외 세관 연동 서비스 | 국가별 데이터 교환 | 트래픽 없는 국가별 엔드포인트 외부 노출 (Dormant) |
| 관세 계산 서비스 | 세율·관세 산출 | 정상 서비스 (대조군) |

## 5. 진행 방침

- 탐지 파이프라인은 **OWASP crAPI로 먼저 검증** → 모의 통관 플랫폼은 시연 무대로 병행 개발 (일정 +1~2주)
- 우선 확보할 원문: USPS 사례 (KrebsOnSecurity 보도, 미국 우정청 감사관실 보고서)
- 거버넌스 조사: UNI-PASS, AEO 인증 기준 IT 보안 항목, WCO 데이터·IT 가이드
