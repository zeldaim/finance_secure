# 01. Shadow API와 Zombie API의 차이

> 프로젝트 내 용어 통일 문서. 탐지 파이프라인의 분류 기준이 된다.

---

## 1. 한눈에 비교

| 구분 | Shadow API | Zombie API |
|---|---|---|
| 한 줄 정의 | **존재 자체를 조직이 모르는** API | **죽었어야 하는데 살아 있는** API |
| 문서(명세)상 상태 | 명세·인벤토리에 **없음** | 명세에 **있었거나 폐기(deprecated) 표시됨** |
| 조직의 인지 | 모름 | 알았지만 잊었거나, 폐기했다고 믿음 |
| 대표 발생 원인 | 승인 없는 배포, 테스트·디버그 엔드포인트, 문서화 누락, 파트너 연동용 임시 API | 신버전(v2) 배포 후 구버전(v1) 미삭제, 폐기 절차 부재, 일부 클라이언트 호환성 때문에 유지 |
| 보안 수준 | 처음부터 보안 검토를 받지 않은 경우가 많음 | 과거 기준으로 만들어져 **최신 보안 패치·정책(인증·레이트리밋)이 빠짐** |
| 모니터링 | 대상 목록에 없어 관측·로깅 사각지대 | 관리 우선순위에서 밀려 로그를 보는 사람이 없음 |
| 탐지 기준(파이프라인) | **관측·자산 − 명세** | **명세상 deprecated/구버전 ∩ 관측·자산** |
| OWASP API Top 10 (2023) | API9 부적절한 인벤토리 관리 | API9 부적절한 인벤토리 관리 |
| 통관·물류 예시 | 포워더 연동 테스트용으로 만든 화물조회 API가 그대로 운영 중 | EDI→REST 전환 후에도 구버전 신고 조회 API가 응답 |

## 2. 관계 — 같은 문제의 두 얼굴

```
                     조직이 알고 있나?
                    예                아니오
              ┌──────────────┬──────────────────┐
  운영돼야    │ Documented   │ Shadow API       │
  하나?  예   │ (정상)        │ (모르는 운영)     │
              ├──────────────┼──────────────────┤
        아니오│ Zombie API   │ Orphan/Ghost     │
              │ (안다고 착각)  │ (주인도 목적도 없음)│
              └──────────────┴──────────────────┘
```

- 둘 다 **"인벤토리와 현실의 불일치"** 라는 같은 뿌리를 가진다.
- Zombie는 시간이 지나면서 담당자가 바뀌면 **Shadow로 변한다**(아무도 기억하지 못하게 됨).
- 따라서 탐지 도구는 둘을 따로 보는 게 아니라 **명세 × 관측 × 자산 3원 대조**로 함께 분류해야 한다.

## 3. 파생 분류 (프로젝트에서 함께 사용)

| 분류 | 설명 |
|---|---|
| **Orphan / Ghost** | 소유 팀·담당자 정보(K8s 라벨, AWS 태그)가 없는 API. 자동화(GitOps, 오토스케일링) 때문에 지워도 되살아나기도 함 |
| **Dormant(휴면) 노출** | 트래픽은 거의 없지만 외부에 열려 있음. 트래픽 미러링만으로는 보이지 않아 자산 조회가 필요 |
| **Phantom 명세** | 명세에는 있지만 실제로는 없음. 보안 위협은 낮지만 문서 품질 문제로 함께 보고 |

## 4. 위험도가 다른 이유

- **Shadow**: 보안 검토를 한 번도 받지 않았을 가능성 → 인증 누락 같은 **기본기 결함** 위험
- **Zombie**: 한때 정상이었지만 **보안 정책이 갱신되지 않음** → 신버전에서 막은 문제가 구버전에 그대로 남음
- 공통: 이상 징후가 생겨도 **보는 사람이 없음** → 침해 인지가 늦어짐

## 5. 대응 원칙

| 대상 | 대응 |
|---|---|
| Shadow | 발견 → 소유자 확인 → 명세 등록 후 정식 관리 **또는** 차단·삭제 |
| Zombie | API 수명주기 정책(폐기 공지 → 유예 기간 → 트래픽 확인 → 삭제) 수립과 자동 점검 |
| 공통 | 배포 파이프라인(CI/CD)에 "명세 없는 API 배포 금지" 게이트, 정기가 아닌 **지속적** 인벤토리 대조 |
