# ShadowAPI 탐지 프로젝트 — 계획 문서

> **통관·물류 플랫폼(EKS)에서 명세 × 트래픽 × 자산 3원 대조로 Shadow/Zombie API를 자동 탐지하는 오픈소스 파이프라인**

## 개요

- **문제**: 마이크로서비스·쿠버네티스·클라우드 자동화 환경에서는 API와 자원이 사람이 관리하는 속도보다 빠르게 생긴다. 문서(명세)에 없는 **Shadow API**, 폐기됐어야 할 **Zombie API**, 주인 없는 **Ghost** 자원이 외부에 노출된 채 방치된다.
- **기존 방어의 한계**: 방화벽(L3/L4)·WAF·API Gateway는 모두 "알고 있는 자산"을 전제로 동작한다. **모르는 자산은 지킬 수 없다.**
- **해법**: 명세(Spec) × 관측 트래픽(Traffic) × 자산 조회(Inventory)를 자동 대조해 미관리 API를 찾고, 위험도를 매겨 리포트한다.
- **무대**: 다수 파트너·다국적 트래픽·EDI→API 전환기가 겹치는 **통관·물류**

## 흐름

```
① 원인 분석 → ② 탐지 파이프라인 구현 → ③ 방화벽/WAF 대비 비교 실험 → ④ 법규·평가 기준 개선 제언
```
