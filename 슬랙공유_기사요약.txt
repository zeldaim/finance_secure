■ 프로젝트 랩 인프라 방향 (FortiGate vs 리눅스 방화벽 검토 결과)

[랩 구성]
공격 스크립트 → 조회 API(FastAPI, vuln/safe 모드) → 구조화 로그(JSON)
→ 탐지 엔진(룰 기반 점수화, 선택: Isolation Forest) → 대응(IP 차단 / step-up 인증)

[방화벽 선택]
· FortiGate — OpenVPN 미지원(SSL VPN은 FortiClient 전용, IPsec은 표준), CLI 의존도 높음
  └ 이번 랩은 계층 분리가 방화벽 역할을 하므로 VPN 불필요
  └ 단, 하이브리드(온프레미스+클라우드) 환경 구축 시에는 필요
· 채택안: 리눅스 iptables + Wazuh
  - Wazuh Active Response가 탐지 시 iptables로 공격 IP 자동 차단 → 궁합 좋음
  - 방화벽 로그가 리눅스 로그로 남아 Wazuh 에이전트가 그대로 수집, 스크립트로 재현 쉬움
  - 리눅스 VM 1대를 라우터 겸 네트워크 방화벽(iptables FORWARD)으로 두어
    웹 → WAS → DB 계층 분리 시연

[한계]
- 실제 금융권은 호스트 방화벽 + 망 경계 전용 방화벽을 함께 사용
- FortiGate 로그도 syslog로 Wazuh 연동 가능하지만, 자동 차단은 별도 API 연동 필요
